# redspec conventions

Generated by `redspec sync`. Edit `spec.config.ts`, not this file.

**Bundles**: `{{specsDir}}/<slug>/` holds `BRIEF.md`, `spec.ts`, `copy.ts`, `fixtures.ts`, `sketches.tsx`, `rules/`, `slices/`, and `.spec-lock.json`. The slug is lowercase and hyphenated and must equal `spec.slug`.

**Spec route**: `{{route}}` lists the specs, `{{route}}/<slug>` is one feature's board, `{{route}}/<slug>/<STATE-id>` renders one case alone. Selected by slug and by **full state ID**, so a URL, a test name, and a slice's claim are the same string. {{gate}}

**What a feature declares** (`spec.ts`, `export default defineSpec({...})`):

- `surfaces` — each screen answers the twelve-row checklist with `{ state }` or `{ waived, witness?, review? }`. Typed as a full record: a row left out is a compile error.
- `states` — one line per declared state: what the person is looking at, in words. Written at declaration, not at render, because the board is read for the whole stretch when nothing renders. A missing name, or one that just repeats the row or the ID, is `unnamed-state`.
- `cases` — the rendered states, each naming its `surface` and a `render`. Empty after `/draft-skeleton`.
- `flows` — one per actor: a `spine` of `{ case, on }` steps ending in `{ case, end }`, with `deviations` of `{ from, when, case }` plus `rejoins` or `end`.
- `copy.ts` — `defineCopy({ "COPY-…": "…" })`. Sketches render from it; assertions assert against it. A state digests the entries **its own assertion names**, so the reference has to be a real one — `copy["COPY-…"]`, not the ID loose in a comment.

Every reference to a case is a plain string, so the skeleton compiles and is red.

**Commands**:

| Purpose                                          | Command                                   |
| ------------------------------------------------ | ----------------------------------------- |
| The work list, in English                        | `redspec status`                          |
| The gate: audit, coverage, lock, tables          | `redspec check`                           |
| Scaffold a feature, state, rule, slice, journeys | `redspec new <kind> …`                    |
| Re-stamp after a passing run                     | `redspec accept <ID…>` / `--slice <path>` |
| Open the board                                   | `redspec board`                           |
| Rules, invariants, unit tests                    | `{{unitCommand}}`                         |
| State tier (spec route, fixtures only)           | `{{stateCommand}}`                        |
| Journey tier (real app)                          | `{{journeyCommand}}`                      |

**Findings** `redspec status` groups them:

| Group    | Kinds                                                                                                                                                                                              | Means                                                            |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| unnamed  | `unnamed-state`                                                                                                                                                                                    | a state declared with only an ID, or a name that repeats its row |
| declared | `declared-not-rendered`                                                                                                                                                                            | the skeleton doing its job; `/render-states` clears it           |
| shape    | `off-path`, `off-checklist`, `unclaimed-id`, `unknown-surface`, `surface-mismatch`, `dangling-deviation`, `deviation-off-deviation`, `compound-actor`, `spine-ends-early`, `empty-spine`, `bad-id` | the registry disagrees with itself                               |
| waivers  | `waiver-due`, `waiver-unwitnessed`, `unknown-witness`                                                                                                                                              | a claim about the product needs re-reading                       |
| bundle   | `actor-without-flow`, `missing-brief`, `unregistered-feature`, `unknown-copy`                                                                                                                      | the bundle on disk disagrees with the registry                   |
| config   | `board-published`                                                                                                                                                                                  | the repo disagrees with its own declarations                     |
| rules    | `table-gap`, `table-overlap`, `table-parse`, `unknown-state-outcome`                                                                                                                               | a decision table is not total, or routes nowhere                 |
| coverage | `orphan`, `claimless`, `unknown-id`, `claimed-twice`                                                                                                                                               | artifacts and slices disagree                                    |
| amended  | `amended`, `unverified`                                                                                                                                                                            | something moved since it was verified, or was never verified     |

**IDs**: `STATE-`, `JOURNEY-`, `RULE-`, `INV-`, `COPY-`, `SURFACE-`, lowercase and hyphenated after the prefix. A rule's ID is its filename; a surface's is `SURFACE-<slug>-<key>`.

**Resolution tables**: a decision table whose outcome column is named `state` routes to states rather than to values. Every outcome must be a declared state (`unknown-state-outcome` otherwise); a state a resolution table routes to counts as reached, and still owes the checklist a row.

**What is in a digest** — change any of it after an artifact is stamped and `check` says `amended`:

| Kind      | Its meaning is                                                                                                               |
| --------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `STATE`   | surface, checklist row, declared name, assertion, screenshot baseline, and the `COPY-` entries the assertion asserts against |
| `JOURNEY` | actor, ordered spine, deviations, and every edge label                                                                       |
| `SURFACE` | the screen's title, the twelve answers, waiver reasons, witnesses, and review dates                                          |
| `RULE`    | the normalized markdown and code                                                                                             |

**Never hand-write into `{{specsDir}}/`** what `redspec new` scaffolds. Never edit `.spec-lock.json`; `redspec accept` writes it after a passing run.
